# RF-033 — Aprobación o rechazo de solicitudes de servicio (administrador)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-033 |
| Nombre | Aprobación o rechazo de solicitudes de servicio |
| Módulo | Administración / Citas y agendamiento |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al administrador aprobar o rechazar las solicitudes de servicio de los clientes. En Neodomus las solicitudes de servicio son las citas que los clientes crean en estado "Pendiente". El administrador las revisa en `AdminInstalaciones.tsx` (datos de `GET /api/v1/citas/all-admin`) y, mediante `PUT /api/v1/citas/admin/{cita_id}`, puede aprobarlas (cambiando el estado a "Confirmada") o rechazarlas (cambiándolo a "Cancelada"), además de asignar técnico. No existe un flujo formal de aprobación con motivo de rechazo ni notificación por correo al cliente.

- **Entradas:**
  - ID de la cita (`cita_id`).
  - `AdminCitaUpdate`: `estado` (Pendiente, Confirmada, Finalizada, Cancelada), `id_tecnico`, `nombre_tecnico`.
  - Token JWT de administrador.

- **Proceso:**
  i. El cliente crea una cita en estado "Pendiente" (RF-008).
  ii. El administrador abre `fe/src/pages/admin/AdminInstalaciones.tsx`, que consulta todas las citas con `GET /api/v1/citas/all-admin`.
  iii. Para aprobar: envía `PUT /api/v1/citas/admin/{cita_id}` con `estado: "Confirmada"`.
  iv. Para rechazar: envía la misma petición con `estado: "Cancelada"`.
  v. `gestionar_cita_admin` (`be/app/routers/citas.py`) valida el estado contra `ESTADOS_CITA` y, si se asigna técnico, aplica las validaciones de especialidad y disponibilidad.
  vi. El cliente ve el nuevo estado en "Mis citas" (`GET /api/v1/citas/mis-citas`).

- **Salidas:**
  - Cita en estado "Confirmada" (aprobada) o "Cancelada" (rechazada).
  - Respuesta HTTP `AdminCitaResponse` con `cliente_nombre` y `cliente_email`.
  - Estado visible para el cliente en su lista de citas.

- **Reglas de negocio:**
  - Los estados permitidos son: Pendiente, Confirmada, Finalizada, Cancelada.
  - No se envía correo de notificación al cliente ni se solicita un motivo al rechazar.

- **Evidencia técnica:**
  - `be/app/routers/citas.py` → `GET /citas/all-admin`, `PUT /citas/admin/{cita_id}` (`gestionar_cita_admin`)
  - `fe/src/pages/admin/AdminInstalaciones.tsx`
