# RF-031 — Suspensión o deshabilitación temporal de usuarios o técnicos (administrador)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-031 |
| Nombre | Suspensión o deshabilitación temporal de usuarios o técnicos |
| Módulo | Administración / Gestión de personal |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al administrador suspender o deshabilitar temporalmente usuarios o técnicos inactivos o con faltas graves. Neodomus lo implementa desactivando la cuenta del empleado: `DELETE /api/v1/users/{user_id}` establece `is_active=False` (el usuario no puede iniciar sesión), y `PUT /api/v1/users/{user_id}` permite alternar el campo `is_active` desde el panel de técnicos. Para los clientes, la deshabilitación se gestiona mediante las solicitudes de cuenta (RF-021). El administrador no puede desactivar su propia cuenta.

- **Entradas:**
  - ID del usuario (`user_id`) o del técnico (`tecnico_id`).
  - Token JWT de administrador.

- **Proceso:**
  i. El administrador abre `fe/src/pages/admin/AdminTecnicos.tsx`.
  ii. Para suspender: el frontend llama a `DELETE /api/v1/users/{user_id}`; `desactivar_empleado` (`be/app/routers/users.py`) valida que no sea la propia cuenta y establece `is_active = False`.
  iii. Alternativa: `PUT /api/v1/users/{user_id}` con `is_active: false` desde la edición del técnico.
  iv. El usuario suspendido recibe 401/403 al intentar autenticarse.
  v. En el panel de técnicos, `GET /api/v1/tecnicos` muestra el estado `is_active` de cada uno.

- **Salidas:**
  - Cuenta del empleado desactivada (`is_active=False`).
  - Respuesta HTTP `{"msg": "Usuario desactivado", "id": ...}`.
  - Lista de técnicos actualizada con su estado.

- **Reglas de negocio:**
  - No se puede desactivar la propia cuenta del administrador.
  - La desactivación no elimina los datos del usuario (baja lógica).
  - Los clientes se deshabilitan mediante solicitudes de cuenta aprobadas (RF-021).

- **Evidencia técnica:**
  - `be/app/routers/users.py` → `DELETE /users/{user_id}` (`desactivar_empleado`), `PUT /users/{user_id}` (campo `is_active`)
  - `be/app/routers/solicitudes.py` → aprobación de solicitudes tipo `inhabilitar`
  - `fe/src/pages/admin/AdminTecnicos.tsx`
