# RF-006 — Visualización del catálogo de servicios domóticos

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-006 |
| Nombre | Visualización del catálogo de servicios domóticos |
| Módulo | Catálogo y productos |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al usuario (visitante o cliente) consultar el catálogo de productos y servicios domóticos de Neodomus. En la implementación real el catálogo está compuesto por **productos domóticos** (dispositivos: sensores, controladores, iluminación, automatización, seguridad, etc.) organizados en categorías, visibles en las páginas públicas y del cliente. Los tipos de servicio de instalación/mantenimiento existen como datos sembrados en la tabla `tipos_servicios`, pero sin endpoints ni pantalla propia; la solicitud de atención se gestiona mediante el formulario de citas (ver RF-008).

- **Entradas:**
  - Ninguna obligatoria (acceso público).
  - Parámetros de consulta opcionales: `search`, `categoria`, `estado`, `page`, `limit`.

- **Proceso:**
  i. El usuario abre la página pública de productos (`fe/src/pages/public/ProductosPublicos.tsx`) o el panel del cliente (`fe/src/pages/cliente/ClientDashboard.tsx`).
  ii. El frontend solicita las categorías con `GET /api/v1/productos/categorias` y el listado con `GET /api/v1/productos/?limit=100`.
  iii. `listar_productos` (`be/app/routers/productos.py`) consulta la tabla `productos` paginada y agrega el campo `stock_estado` (`agotado`, `bajo` o `disponible` según `STOCK_MINIMO = 5`).
  iv. El catálogo se renderiza en tarjetas con imagen, nombre y precio, con búsqueda, filtros por categoría y paginación en el cliente.
  v. El usuario puede marcar productos como favoritos (persistidos localmente en `localStorage`) y agregarlos al carrito.

- **Salidas:**
  - Respuesta JSON paginada `{total, page, limit, data, total_pages}` con los productos y su estado de stock.
  - Lista de categorías desde la base de datos.
  - Pantalla de catálogo con tarjetas, buscador, filtros y paginación.

- **Reglas de negocio:**
  - Solo se muestran los productos (estado de catálogo) configurados como disponibles.
  - El estado de stock se deriva del umbral `STOCK_MINIMO = 5` (bajo si hay de 1 a 4 unidades, agotado si es 0).

- **Evidencia técnica:**
  - `be/app/routers/productos.py` → `GET /productos/`, `GET /productos/categorias`
  - `be/app/models/producto.py`, `be/app/models/categoria.py`
  - `fe/src/pages/public/ProductosPublicos.tsx`, `fe/src/pages/cliente/ClientDashboard.tsx`
  - `fe/src/constants.ts` → `STOCK_MINIMO`
