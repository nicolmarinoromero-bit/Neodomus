# RF-002 — Registro de proveedores y técnicos por el administrador

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-002 |
| Nombre | Registro de proveedores y técnicos por el administrador |
| Módulo | Administración / Gestión de personal |
| Prioridad | Alta |
| Estado | Parcialmente implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al administrador crear cuentas para empleados de la plataforma, entre ellos los técnicos, con sus datos personales y rol correspondiente. El ingreso de técnicos está totalmente implementado (incluida la ficha técnica con certificación y cargo). Sin embargo, **no existe un CRUD de proveedores**: la tabla `proveedores` solo se lee (lista de proveedores para el módulo de productos) y no hay endpoints ni pantallas para crearlos, editarlos o eliminarlos desde la administración.

- **Entradas:**
  - Nombres (`first_name`), Apellidos (`last_name`).
  - Correo electrónico (`email`, único).
  - Contraseña (`password`, la define el administrador; mínimo 6 caracteres).
  - Teléfono (`telefono_usuario`).
  - Número de documento (`documento_usuario`, único).
  - Rol (`id_rol`, por defecto 2 = técnico; roles sembrados: 1 = administrador, 2 = técnico).
  - Para técnicos: certificación (`certificacion`) y cargo (`cargo`).

- **Proceso:**
  i. El administrador abre `fe/src/pages/admin/AdminTecnicos.tsx` y completa el formulario de nuevo usuario.
  ii. El frontend llama a `POST /api/v1/users` con el cuerpo `EmployeeCreate` incluyendo el `id_rol`.
  iii. `crear_empleado` (`be/app/routers/users.py`) valida la unicidad de correo y documento y que el rol exista en `roles_usuario`.
  iv. La contraseña se almacena con hash bcrypt y se crea el `User` con `is_active=True`.
  v. Si el rol es `tecnico`, se crea automáticamente la ficha en la tabla `tecnicos` (certificación y cargo).
  vi. La cuenta queda lista para iniciar sesión (el administrador comunica las credenciales por fuera; el sistema no envía correo de bienvenida al empleado).
  vii. Para proveedores no existe flujo: la tabla `proveedores` solo aparece en `GET /api/v1/productos/proveedores` (solo lectura).

- **Salidas:**
  - Nuevo `User` en la tabla `usuarios` (y `Tecnico` en `tecnicos` si aplica).
  - Respuesta HTTP `{"msg": "Usuario registrado correctamente", "id": ..., "email": ...}`.
  - Actualización de la lista de técnicos en el panel de administración.

- **Reglas de negocio:**
  - Solo el administrador puede crear empleados (helper `_admin` en `users.py`; compara rol contra `admin`/`administrador`).
  - El correo y el documento no pueden estar duplicados.
  - Si el rol es técnico, la ficha técnica se crea automáticamente.
  - No se puede desactivar la propia cuenta del administrador.

- **Evidencia técnica:**
  - `be/app/routers/users.py` → `POST /users` (`crear_empleado`)
  - `be/app/routers/productos.py` → `GET /productos/proveedores` (única lectura de proveedores)
  - `be/app/models/user.py`, `be/app/models/tecnico.py`, `be/app/models/proveedor.py`, `be/app/models/roles_usuario.py`
  - `fe/src/pages/admin/AdminTecnicos.tsx`
