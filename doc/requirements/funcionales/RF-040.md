# RF-040 — Copias de seguridad automáticas

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-040 |
| Nombre | Copias de seguridad automáticas de la información |
| Módulo | Seguridad / Infraestructura |
| Prioridad | Media |
| Estado | No implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El requisito exige realizar copias de seguridad automáticas de la información almacenada en el sistema. En Neodomus **no existe ningún mecanismo de respaldo automático**: no hay scripts de `mysqldump`, no hay tareas programadas (cron), ni un servicio de backup en `docker-compose.yml`. La única protección de datos es el **volumen Docker `mysql_data`**, que persiste la base de datos localmente (útil ante reinicios del contenedor, pero no ante fallos del disco o del host, y no genera copias de seguridad periódicas). Las restricciones del proyecto (RC, HU-43, RNF-02.2) documentaban el respaldo cada 24 horas, sin implementación.

- **Entradas:**
  - (No aplica: no existe la funcionalidad.)

- **Proceso:**
  i. No existe ningún servicio, script ni tarea que genere copias de la base de datos.
  ii. `docker-compose.yml` monta `mysql_data` como volumen de persistencia del motor MySQL.

- **Salidas:**
  - Ninguna copia de seguridad automática.
  - Únicamente persistencia del volumen de datos local.

- **Reglas de negocio:**
  - No implementadas (frecuencia de 24 h y restauración documentadas en RNF-02.2/RNF-02.3, sin implementación).

- **Evidencia técnica:**
  - `docker-compose.yml` (volumen `mysql_data`, sin servicio de backup)
  - Ausencia de scripts de backup en el repositorio (verificado)
