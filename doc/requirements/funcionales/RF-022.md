# RF-022 — Visualización de servicios asignados (técnico)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-022 |
| Nombre | Visualización de los servicios asignados (técnico) |
| Módulo | Módulo del técnico |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al técnico ver todos los servicios (citas) que le han sido asignados. Neodomus lo implementa con `GET /api/v1/tecnicos/mis-citas`, que devuelve únicamente las citas cuyo `id_tecnico` corresponde a la ficha técnica del empleado autenticado, ordenadas por fecha y hora. El técnico dispone de las pantallas `TechnicianDashboard.tsx` y `TecnicoCitas.tsx` (con pestañas y filtros por estado).

- **Entradas:**
  - Token JWT de empleado con ficha técnica (`id_usuario_t`).
  - (Opcional) Filtro por estado en el panel.

- **Proceso:**
  i. El técnico inicia sesión y entra a su panel (`TechnicianDashboard.tsx` o `TecnicoCitas.tsx`).
  ii. El frontend llama a `GET /api/v1/tecnicos/mis-citas`.
  iii. `mis_citas_tecnico` (`be/app/routers/tecnicos.py`) busca la ficha del técnico autenticado y devuelve sus citas con datos del cliente (nombre, teléfono), dirección, tipo de servicio, fecha, hora y estado.
  iv. La interfaz lista las citas y permite filtrarlas por estado.

- **Salidas:**
  - Lista de citas asignadas al técnico con estado y datos del cliente.
  - Respuesta HTTP `List[TecnicoCitaResponse]`.

- **Reglas de negocio:**
  - El técnico solo ve sus propias citas (filtro por su `id_tecnico`).
  - Si el empleado no tiene ficha técnica, el endpoint responde 404.

- **Evidencia técnica:**
  - `be/app/routers/tecnicos.py` → `GET /tecnicos/mis-citas`
  - `fe/src/pages/tecnico/TechnicianDashboard.tsx`, `fe/src/pages/tecnico/TecnicoCitas.tsx`
