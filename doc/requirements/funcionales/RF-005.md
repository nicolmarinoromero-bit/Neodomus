# RF-005 — Recuperación de contraseña

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-005 |
| Nombre | Recuperación de contraseña |
| Módulo | Autenticación / Gestión de cuentas |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite a clientes y empleados (técnicos y administradores) recuperar el acceso a su cuenta cuando olvidan la contraseña. El requisito solicita un enlace al correo; Neodomus implementa un mecanismo equivalente pero distinto: envía un **código OTP de 6 dígitos** al correo registrado, válido por 10 minutos, que debe ingresarse para luego definir la nueva contraseña. Este mecanismo está documentado desde abril de 2026 en `doc/requirements/user-stories.md` (HU-04) y `doc/requirements/constraints.md` (RC-04.4).

- **Entradas:**
  - Correo electrónico registrado (`email`).
  - Código OTP de 6 dígitos recibido por correo (`code`).
  - Nueva contraseña (`new_password`, mínimo 8 caracteres con mayúscula, minúscula y número).

- **Proceso:**
  i. El usuario elige "¿Olvidaste tu contraseña?" en el login y envía su correo en `fe/src/pages/auth/ForgotPassword.tsx`.
  ii. El frontend llama a `POST /api/v1/auth/forgot-password`.
  iii. `request_password_reset` (`be/app/services/auth_service.py`) se ejecuta como tarea en segundo plano (`BackgroundTasks`): si el correo existe en `clientes` o `usuarios`, crea un registro en `password_reset_tokens` con código de 6 dígitos y expiración de 10 minutos (`PASSWORD_RESET_TOKEN_EXPIRE_MINUTES`), y envía el correo con `send_password_reset_code`.
  iv. Si el correo no está registrado, la respuesta es idéntica ("Si el email está registrado, recibirás un código de recuperación") para no revelar cuentas existentes.
  v. El usuario ingresa el código en `fe/src/pages/auth/VerifyCode.tsx`, que llama a `POST /api/v1/auth/verify-code`; el endpoint valida vigencia y uso sin marcarlo como usado.
  vi. El usuario define la nueva contraseña en `fe/src/pages/auth/ResetPassword.tsx`, que llama a `POST /api/v1/auth/reset-password`.
  vii. `reset_password` valida el código, actualiza `password_hash` (bcrypt) del cliente o empleado según `user_type` y marca el token como `used=True`.
  viii. Se registra auditoría `PASSWORD_RESET_REQUESTED` y `PASSWORD_CHANGED`.

- **Salidas:**
  - Correo "Neodomus - Código para restablecer tu contraseña" con el OTP de 6 dígitos.
  - Respuesta `{"msg": "Si el email está registrado, recibirás un código de recuperación"}`.
  - Verificación de código: `{"valid": true, "message": ...}`.
  - Actualización de la contraseña en la base de datos y mensaje "Contraseña actualizada correctamente".
  - Redirección al login para iniciar sesión con la nueva contraseña.

- **Reglas de negocio:**
  - El código de recuperación expira a los 10 minutos de su generación.
  - Un código solo puede usarse una vez (se marca `used=True` al restablecer).
  - El sistema no revela si un correo existe o no en la plataforma.
  - No se implementa el bloqueo por IP tras 5 intentos fallidos documentado en RC-04.4: el rate limiting está instalado (`slowapi`) pero no aplicado a ningún endpoint.

- **Evidencia técnica:**
  - `be/app/routers/auth.py` → `POST /auth/forgot-password`, `POST /auth/verify-code`, `POST /auth/reset-password`
  - `be/app/services/auth_service.py` → `request_password_reset`, `verify_password_reset_code`, `reset_password`
  - `be/app/models/password_reset_token.py`, `be/app/utils/email.py` → `send_password_reset_code`
  - `be/app/utils/audit_log.py` → `PASSWORD_RESET_REQUESTED`, `PASSWORD_CHANGED`
  - `fe/src/pages/auth/ForgotPassword.tsx`, `VerifyCode.tsx`, `ResetPassword.tsx`
