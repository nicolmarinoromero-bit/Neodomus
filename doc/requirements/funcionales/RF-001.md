# RF-001 — Registro de usuarios (clientes) en la plataforma

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-001 |
| Nombre | Registro de usuarios (clientes) en la plataforma |
| Módulo | Autenticación / Gestión de cuentas |
| Prioridad | Alta |
| Estado | Parcialmente implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite a un cliente crear su cuenta en Neodomus ingresando sus datos personales. El registro es público: cualquier persona puede iniciarlo desde el sitio web. A diferencia de lo solicitado en el requisito, el sistema no pide un "nombre de usuario": la identificación se realiza mediante el correo electrónico, por lo que el campo de usuario no existe. Además, el registro se completa en dos pasos: el cliente envía sus datos y luego debe verificar el correo electrónico con un código de 6 dígitos para que la cuenta quede activa.

- **Entradas:**
  - Nombres (`first_name`).
  - Apellidos (`last_name`).
  - Tipo de documento (`id_tipo_documento_c`, valores sembrados: `cc`, `ce`).
  - Número de documento (`documento_cliente`, único).
  - Correo electrónico (`email`, único).
  - Contraseña (`password`, mínimo 8 caracteres con mayúscula, minúscula y número).
  - Número de teléfono (`telefono_cliente`).
  - Dirección (`address`).
  - En el frontend además: ciudad y municipio (fijos a Bogotá D.C.) y aceptación de términos, privacidad y cookies.

- **Proceso:**
  i. El cliente completa el formulario en `fe/src/pages/auth/Register.tsx` y lo envía.
  ii. El frontend llama a `POST /api/v1/auth/register/client` con el cuerpo `ClientCreate`.
  iii. El servicio `register_client` (`be/app/services/auth_service.py`) valida que el correo y el documento no estén registrados (en `clientes` ni en `pending_registrations`) y valida la fortaleza de la contraseña.
  iv. La contraseña se almacena únicamente como hash bcrypt (12 rondas) mediante `hash_password` (`be/app/utils/security.py`); no se guarda en texto plano.
  v. Se genera un código de verificación de 6 dígitos y se registra un registro pendiente en la tabla `pending_registrations` con vigencia de 24 horas (`VERIFICATION_TOKEN_EXPIRE_HOURS`).
  vi. El sistema envía un correo de bienvenida con el código mediante `send_verification_email` (`be/app/utils/email.py`) usando SMTP (Gmail).
  vii. El cliente ingresa el código en `fe/src/pages/auth/VerifyEmail.tsx`, que llama a `POST /api/v1/auth/verify-email`.
  viii. `verify_client_email` valida el código y la vigencia, crea el `Cliente` con `is_active=True` y elimina el registro pendiente.
  ix. La cuenta queda lista para iniciar sesión.

- **Salidas:**
  - Creación del `Cliente` en la base de datos (tabla `clientes`) únicamente tras la verificación del correo.
  - Correo electrónico "Bienvenido a Neodomus - Verifica tu cuenta" con código OTP.
  - Respuesta HTTP con mensaje de éxito (`{"msg": ...}`) del endpoint de registro y el de verificación.
  - Pantalla de verificación de correo en el frontend con opción de reenviar código (`POST /api/v1/auth/resend-verification`).

- **Reglas de negocio:**
  - El correo electrónico es único entre clientes y regímenes pendientes.
  - El número de documento es único por cliente.
  - La cuenta no queda activa hasta que el correo sea verificado.
  - El código de verificación expira a las 24 horas de su generación.

- **Evidencia técnica:**
  - `be/app/routers/auth.py` → `POST /auth/register/client`, `POST /auth/verify-email`, `POST /auth/resend-verification`
  - `be/app/services/auth_service.py` → `register_client`, `verify_client_email`, `resend_verification_code`
  - `be/app/models/pending_registration.py`, `be/app/models/cliente.py`
  - `be/app/utils/security.py` → `hash_password` (bcrypt)
  - `be/app/utils/email.py` → `send_verification_email`
  - `fe/src/pages/auth/Register.tsx`, `fe/src/pages/auth/VerifyEmail.tsx`
  - `fe/src/services/api.ts`
