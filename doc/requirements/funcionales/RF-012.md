# RF-012 — Pagos seguros desde la plataforma

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-012 |
| Nombre | Pagos seguros desde la plataforma |
| Módulo | Pagos y facturación |
| Prioridad | Alta |
| Estado | No implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El requisito exige que el usuario pueda pagar los servicios directamente en la plataforma de forma segura. En Neodomus **no existe ningún módulo de pagos**: no hay pasarela de pago (Stripe, PayPal, MercadoPago, PSE, etc.), no hay tablas de transacciones ni endpoints de cobro. El carrito (`fe/src/pages/public/CarritoPage.tsx`) se gestiona únicamente con `localStorage`, y el botón "Finalizar compra" solo limpia el carrito y muestra un aviso de agradecimiento (`handleFinalizar` → `clearCart()`). Las restricciones RC-02.3 y RC-10 del proyecto documentan que los pagos eran parte del alcance, pero no se implementaron.

- **Entradas:**
  - (No aplica: no existe la funcionalidad.)

- **Proceso:**
  i. El usuario agrega productos al carrito desde el catálogo.
  ii. En `CarritoPage.tsx` el botón "Finalizar compra" invoca `handleFinalizar`, que limpia el carrito y muestra una notificación de "gracias"; no hay paso de pago ni confirmación de pedido.
  iii. No existe llamada a ningún endpoint de pagos ni integración con pasarelas.

- **Salidas:**
  - Carrito vaciado y aviso de agradecimiento en pantalla.
  - No se genera comprobante, transacción ni pedido.

- **Reglas de negocio:**
  - No implementadas (no existe el módulo).

- **Evidencia técnica:**
  - `fe/src/pages/public/CarritoPage.tsx` → `handleFinalizar` (solo `clearCart()`)
  - `fe/src/contexts/CartContext.tsx` (persistencia en `localStorage`)
  - Backend: sin routers ni modelos de pagos (verificado: `be/app/routers/`, `be/app/models/`)
  - `doc/requirements/constraints.md` → RC-02.3, RC-10 (alcance documentado, sin implementar)
