# RF-043 — Envío de comunicados o mensajes masivos (administrador)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-043 |
| Nombre | Envío de comunicados o mensajes masivos |
| Módulo | Administración / Comunicación |
| Prioridad | Baja |
| Estado | No implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El requisito exige que el administrador pueda enviar comunicados o mensajes masivos a proveedores y técnicos. En Neodomus **no existe esta funcionalidad**: no hay endpoint de mensajería masiva ni plantillas de correo para comunicados. La pantalla `AdminNotificaciones.tsx` combina una lista de **notificaciones de demostración estáticas** (`NOTIFICACIONES_DEMO`) con las solicitudes de cuenta reales; no permite redactar ni enviar comunicados a ningún grupo de destinatarios.

- **Entradas:**
  - (No aplica: no existe la funcionalidad.)

- **Proceso:**
  i. El administrador abre `fe/src/pages/admin/AdminNotificaciones.tsx`.
  ii. La pantalla muestra notificaciones de ejemplo sin origen en la API y las solicitudes de cuenta pendientes.
  iii. No existe ningún flujo de envío masivo (correo o campana).

- **Salidas:**
  - Ninguna (no se envían comunicados).

- **Reglas de negocio:**
  - No implementadas (la user story HU-41 documentaba el alcance, sin implementación).

- **Evidencia técnica:**
  - `fe/src/pages/admin/AdminNotificaciones.tsx` (`NOTIFICACIONES_DEMO`)
  - Ausencia de endpoints de mensajería masiva en `be/app/routers/` (verificado)
  - `be/app/utils/email.py` (sin función de envío masivo)
