# RF-038 — Creación, modificación y eliminación de promociones y descuentos (administrador)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-038 |
| Nombre | Gestión de promociones y descuentos especiales |
| Módulo | Administración / Catálogo |
| Prioridad | Baja |
| Estado | No implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El requisito exige que el administrador pueda crear, modificar o eliminar promociones y descuentos especiales. En Neodomus **no existe el módulo de promociones**: el modelo `producto.py` no tiene campos de descuento ni precio promocional, y no hay tablas de promociones ni endpoints para gestionarlas. El archivo `be/app/schemas/producto.py` contiene campos `descuento_activo` y `precio_final`, pero **no se importa en ningún punto** del backend (el router define sus propios esquemas internos). En el frontend, `ProductoDetalle.tsx` muestra una insignia de descuento, pero se trata de una presentación local que el API nunca devuelve.

- **Entradas:**
  - (No aplica: no existe la funcionalidad.)

- **Proceso:**
  i. No existe ningún endpoint de promociones o descuentos en `be/app/routers/`.
  ii. El badge de descuento del frontend es una representación visual sin datos del servidor.

- **Salidas:**
  - Ninguna (sin datos reales de promociones).

- **Reglas de negocio:**
  - No implementadas (la user story HU-37 documentaba el alcance, sin implementación).

- **Evidencia técnica:**
  - `be/app/models/producto.py` (sin campos de descuento)
  - `be/app/schemas/producto.py` (campos de descuento definidos pero sin uso)
  - `fe/src/pages/public/ProductoDetalle.tsx` (insignia visual local)
