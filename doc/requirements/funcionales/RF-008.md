# RF-008 — Solicitud de un servicio (formulario con fecha, hora y tipo de trabajo)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-008 |
| Nombre | Solicitud de un servicio mediante formulario |
| Módulo | Citas y agendamiento |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al cliente registrado solicitar la atención de un servicio domótico agendando una cita. El formulario incluye tipo de servicio (instalación, reparación, mantenimiento o revisión), fecha, hora, dirección y descripción opcional, y permite seleccionar un técnico (opcional). Al crearse, la cita queda en estado "Pendiente". También se registran como citas los pedidos de productos con instalación.

- **Entradas:**
  - Tipo de servicio (`tipo_servicio`: instalación, reparación, mantenimiento, revisión).
  - Fecha (`fecha`, no puede ser anterior al día actual).
  - Hora (`hora`).
  - Dirección (`direccion`).
  - Descripción opcional (`descripcion`).
  - Técnico opcional (`id_tecnico`).
  - Cliente autenticado (token JWT).

- **Proceso:**
  i. El cliente inicia sesión y abre `fe/src/pages/cliente/CitasPage.tsx` (pestaña "Agendar").
  ii. Completa el formulario: tipo de servicio, fecha, hora (grid de horas), dirección y comentarios; opcionalmente selecciona un técnico de la lista (`GET /api/v1/tecnicos/publicos`).
  iii. El frontend envía `POST /api/v1/citas` con `CitaCreate`.
  iv. `crear_cita` (`be/app/routers/citas.py`) valida que la fecha no sea anterior a hoy.
  v. Si se envía `id_tecnico`, se valida que el técnico exista y esté activo, que su especialidad sea compatible con el servicio (`compatible_especialidad` en `be/app/services/especialidades.py`) y que esté libre en esa fecha y hora (`tecnico_ocupado`); el nombre del técnico se obtiene de la base de datos (se ignora cualquier nombre enviado).
  vi. Se crea la `Cita` con `estado="Pendiente"` y se persiste en la base de datos.
  vii. La cita aparece en la pestaña "Mis citas" del cliente.

- **Salidas:**
  - Registro de la cita en la tabla `citas` con estado "Pendiente".
  - Respuesta HTTP `CitaResponse` con los datos de la cita creada.
  - Actualización de la lista "Mis citas" en la interfaz del cliente.

- **Reglas de negocio:**
  - La fecha de la cita no puede ser anterior al día actual.
  - El técnico asignado debe tener la especialidad compatible y no estar ocupado (cita Pendiente o Confirmada) en esa fecha y hora.
  - No se valida el horario de atención configurado (no existe configuración de horarios generales, ver RF-041).

- **Evidencia técnica:**
  - `be/app/routers/citas.py` → `POST /citas` (`crear_cita`)
  - `be/app/services/especialidades.py` → `compatible_especialidad`, `tecnico_ocupado`
  - `be/app/models/cita.py`, `be/app/schemas/cita.py`
  - `fe/src/pages/cliente/CitasPage.tsx`, `fe/src/services/api.ts`
