# RF-018 — Edición de datos personales, dirección, teléfono y contraseña

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-018 |
| Nombre | Edición de datos personales, dirección, teléfono y contraseña |
| Módulo | Autenticación / Gestión de cuentas |
| Prioridad | Media |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite a clientes, técnicos y administradores actualizar sus datos personales: nombre, apellido, documento, teléfono, dirección (los clientes) y contraseña. Los clientes usan `PUT /api/v1/clients/me`; los empleados (técnicos y administradores) usan `PUT /api/v1/users/me` (que además actualiza la ficha técnica de certificación y cargo). El cambio de contraseña se realiza con el endpoint `POST /api/v1/auth/change-password`, que exige la contraseña actual.

- **Entradas:**
  - Cliente: `first_name`, `last_name`, `documento_cliente`, `telefono_cliente`, `email`, `address`.
  - Empleado: `first_name`, `last_name`, `email`, `telefono_usuario`, `documento_usuario`, `certificacion_t`, `cargo_t`.
  - Para cambiar contraseña: `current_password` y `new_password` (mínimo 8 caracteres con mayúscula, minúscula y número).
  - Token JWT del usuario autenticado.

- **Proceso:**
  i. El cliente abre su perfil (`fe/src/pages/cliente/Perfil.tsx`, pestaña "Datos personales") o el empleado su propio perfil (`TecnicoPerfil.tsx`, `AdminPerfil.tsx`).
  ii. El frontend carga el perfil con `GET /clients/me` o `GET /users/me` y envía los cambios con `PUT` al mismo recurso.
  iii. Los routers validan unicidad de correo/documento y que nombre y apellido no estén vacíos, y persisten los cambios.
  iv. Para la contraseña, `fe/src/components/profile/PasswordTab.tsx` (o `ChangePassword.tsx`) envía `POST /api/v1/auth/change-password`; `change_password` verifica la contraseña actual, valida los requisitos de fortaleza, aplica el nuevo hash bcrypt y registra auditoría `PASSWORD_CHANGED`.

- **Salidas:**
  - Perfil actualizado en la base de datos.
  - Respuesta HTTP con los datos del perfil actualizado.
  - Mensaje de confirmación y lista de requisitos cumplidos al cambiar la contraseña.

- **Reglas de negocio:**
  - El correo y el documento no pueden duplicarse entre cuentas.
  - El rol de un usuario nunca se modifica desde la edición de su propio perfil.
  - El cambio de contraseña exige conocer la contraseña actual.

- **Evidencia técnica:**
  - `be/app/routers/clientes.py` → `GET/PUT /clients/me`
  - `be/app/routers/users.py` → `GET/PUT /users/me`
  - `be/app/routers/auth.py` → `POST /auth/change-password`
  - `fe/src/components/profile/PersonalTab.tsx`, `PasswordTab.tsx`; `fe/src/pages/tecnico/TecnicoPerfil.tsx`; `fe/src/pages/admin/AdminPerfil.tsx`
