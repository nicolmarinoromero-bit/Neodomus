# RF-036 — Monitoreo de pagos y transacciones (administrador)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-036 |
| Nombre | Monitoreo de pagos y transacciones |
| Módulo | Administración / Pagos |
| Prioridad | Media |
| Estado | No implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El requisito exige que el administrador pueda monitorear los pagos y las transacciones realizadas en la plataforma. En Neodomus **no existe el módulo de pagos** (ver RF-012): no hay pasarela, no hay tabla de transacciones ni endpoints de pagos, por lo que tampoco existe un panel de monitoreo financiero. El panel de administración solo presenta métricas de ventas agregadas en `AdminReportes.tsx` (`GET /api/v1/reports/resumen`), que usan los campos de la tabla `pedidos` sembrada, sin origen transaccional real.

- **Entradas:**
  - (No aplica: no existe la funcionalidad.)

- **Proceso:**
  i. No existe ninguna pantalla ni endpoint de transacciones de pago.
  ii. El resumen de ventas (`/reports/resumen`) calcula `ventas_total` y `pedidos_total` sobre la tabla `pedidos`, que no se alimenta desde el flujo real de compras (el carrito no crea pedidos).

- **Salidas:**
  - Ninguna relacionada con pagos reales.

- **Reglas de negocio:**
  - No implementadas.

- **Evidencia técnica:**
  - Ausencia de routers/modelos de pagos en `be/app/` (verificado)
  - `be/app/routers/reports.py` → `/reports/resumen` (métricas sobre `pedidos` sembrada)
  - `fe/src/pages/admin/AdminReportes.tsx`
