# RF-037 — Creación, edición y eliminación de servicios del catálogo (administrador)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-037 |
| Nombre | Gestión del catálogo (crear, editar o eliminar servicios) |
| Módulo | Administración / Catálogo |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al administrador crear, editar o eliminar los ítems del catálogo. En Neodomus el catálogo de la plataforma está compuesto por **productos domóticos** (tabla `productos`), y su gestión es completa: `POST /api/v1/productos` (crear), `PUT /api/v1/productos/{producto_id}` (editar) y `DELETE /api/v1/productos/{producto_id}` (eliminar). La eliminación es física cuando no hay historial asociado; si hay referencias en pedidos, la base de datos rechaza el borrado y el sistema aplica una baja lógica (`estado_producto = "inactivo"`). También se gestionan las variantes por color (`POST/PUT/DELETE /api/v1/productos/{producto_id}/variantes[/{variante_id}]`).

- **Entradas:**
  - `nombre_producto`, `referencia_producto` (única, autogenerada como `ref-<nombre>-<timestamp>` si no se envía), `id_proveedor_pr`, `precio_compra_producto`, `precio_venta_producto`, `imagen_url`, `id_cate_pr`, `descripcion_producto`, `colores_producto`, `estado_producto`, `stock_producto`.
  - Para variantes: `nombre`, `hex`, `imagen_url`, `stock`.
  - Token JWT de administrador.

- **Proceso:**
  i. El administrador abre `fe/src/pages/admin/AdminProductos.tsx` o `AdminProductoDetalle.tsx`.
  ii. Para crear: envía `POST /api/v1/productos`; `crear_producto` valida la unicidad de la referencia y guarda el registro.
  iii. Para editar: envía `PUT /api/v1/productos/{producto_id}`.
  iv. Para eliminar: envía `DELETE /api/v1/productos/{producto_id}`; si el borrado físico falla por restricción de integridad (`IntegrityError`), se marca `estado_producto="inactivo"`.
  v. Las variantes se administran desde el detalle del producto.
  vi. Los cambios son visibles de inmediato en el catálogo público (`GET /api/v1/productos/`).

- **Salidas:**
  - Productos creados, actualizados o eliminados (con baja lógica cuando aplica).
  - Respuesta HTTP con el producto o mensaje de confirmación.
  - Catálogo actualizado en las pantallas públicas y del cliente.

- **Reglas de negocio:**
  - La referencia del producto es única.
  - No se pueden eliminar físicamente productos con registros asociados en `detalle_pedido`; se aplica baja lógica.
  - Solo el administrador puede gestionar el catálogo.

- **Evidencia técnica:**
  - `be/app/routers/productos.py` → `POST /productos`, `PUT /productos/{producto_id}`, `DELETE /productos/{producto_id}`, endpoints de variantes
  - `be/app/models/producto.py`, `be/app/models/producto_variante.py`
  - `fe/src/pages/admin/AdminProductoDetalle.tsx`, `AdminProductos.tsx`, `AdminCatalogo.tsx`
