# RF-010 — Visualización del estado de las solicitudes

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-010 |
| Nombre | Visualización del estado de las solicitudes |
| Módulo | Citas y agendamiento |
| Prioridad | Alta |
| Estado | Parcialmente implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  Permite al usuario consultar el estado de cada servicio solicitado. Neodomus muestra los estados de las citas en la pestaña "Mis citas" del cliente. El requisito contempla cinco estados (Pendiente, En proceso, Confirmado, Cancelado, Finalizado); el sistema implementa cuatro estados reales: **Pendiente, Confirmada, Finalizada y Cancelada** (definidos en `be/app/routers/citas.py`). El estado "En proceso" **no existe** en la implementación.

- **Entradas:**
  - Cliente autenticado.
  - ID de cita (para el detalle).

- **Proceso:**
  i. El cliente abre la pestaña "Mis citas" de `fe/src/pages/cliente/CitasPage.tsx`.
  ii. El frontend llama a `GET /api/v1/citas/mis-citas`.
  iii. `mis_citas` (`be/app/routers/citas.py`) devuelve las citas del cliente ordenadas por fecha y hora, cada una con su campo `estado`.
  iv. La interfaz lista cada cita con su estado (Pendiente, Confirmada, Finalizada o Cancelada).

- **Salidas:**
  - Lista de citas del cliente con su estado actual y detalles (fecha, hora, tipo de servicio, técnico asignado si existe, dirección).
  - Respuesta HTTP `List[CitaResponse]`.

- **Reglas de negocio:**
  - Los estados posibles de una cita son: `Pendiente`, `Confirmada`, `Finalizada` y `Cancelada`.
  - No existe el estado "En proceso"; la transición típica es Pendiente → Confirmada → Finalizada (o Cancelada).

- **Evidencia técnica:**
  - `be/app/routers/citas.py` → `GET /citas/mis-citas`, `ESTADOS_CITA`
  - `be/app/models/cita.py` (campo `estado`)
  - `fe/src/pages/cliente/CitasPage.tsx`
