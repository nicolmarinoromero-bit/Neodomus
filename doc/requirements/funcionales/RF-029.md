# RF-029 — Registro y actualización de la disponibilidad laboral (técnico)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RF-029 |
| Nombre | Registro y actualización de la disponibilidad laboral (técnico) |
| Módulo | Módulo del técnico |
| Prioridad | Media |
| Estado | No implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El requisito exige que el técnico registre y actualice los días y horarios en los que está disponible para trabajar. En Neodomus **no existe esta funcionalidad**: no hay tabla de disponibilidad, ni endpoints para registrarla o modificarla, ni pantalla en el panel del técnico. La única noción de "disponibilidad" es indirecta: el sistema calcula si un técnico está libre en una fecha y hora determinadas revisando si tiene citas Pendientes o Confirmadas en ese horario (`tecnico_ocupado`), pero el técnico no puede declarar su disponibilidad.

- **Entradas:**
  - (No aplica: no existe la funcionalidad.)

- **Proceso:**
  i. No existe ningún endpoint de disponibilidad en `be/app/routers/tecnicos.py`.
  ii. `tecnico_ocupado` (`be/app/services/especialidades.py`) solo marca al técnico como no disponible si tiene una cita activa en el horario consultado.

- **Salidas:**
  - Ninguna (la disponibilidad es derivada de las citas existentes, no configurable).

- **Reglas de negocio:**
  - No implementadas (la user story HU-26 documentaba el alcance, sin implementación).

- **Evidencia técnica:**
  - Ausencia de endpoints/tablas de disponibilidad en `be/app/` (verificado)
  - `be/app/services/especialidades.py` → `tecnico_ocupado`
