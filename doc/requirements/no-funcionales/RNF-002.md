# RNF-002 — Escalabilidad / Rendimiento

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RNF-002 |
| Nombre | Escalabilidad / Rendimiento |
| Categoría | Rendimiento |
| Prioridad | Media |
| Estado | No implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  La plataforma debe soportar al menos 500 usuarios concurrentes sin afectar el tiempo de respuesta, con un máximo de 3 segundos por operación.

- **Criterio:**  
  - Soportar 500 usuarios concurrentes en condiciones normales de operación.
  - Tiempo de respuesta máximo de 3 segundos (la documentación interna detalla: lectura ≤ 500 ms, escritura ≤ 1 s, carga inicial ≤ 3 s).

- **Implementación actual:**  
  - La API (FastAPI + SQLAlchemy) está contenedorizada con `docker-compose` y la base de datos MySQL usa `pool_pre_ping=True` y `pool_recycle=3600`, condiciones razonables de punto de partida.
  - **No existe ninguna prueba de carga ni de concurrencia** (no hay scripts con herramientas como Locust, K6, JMeter ni métricas registradas).
  - Las consultas del catálogo están paginadas (`page`/`limit`), lo que limita el tamaño de las respuestas.
  - No hay caché (Redis/Memcached) ni balanceo de carga configurado en el entorno actual.

- **Evidencia técnica:**  
  - `be/app/database.py` → `pool_pre_ping`, `pool_recycle`
  - `docker-compose.yml` → servicios `api`, `frontend`, `db`
  - `be/app/routers/productos.py` → paginación en `GET /productos/`
  - `fe/src/services/api.ts` → consumo paginado del catálogo
  - `doc/requirements/non-functional.md` → RNF-01.1 a RNF-01.4 (métricas documentadas)

- **Validación:**  
  - Ejecutar una prueba de carga simulando 500 usuarios concurrentes (p. ej. con Locust o K6) y medir latencias y errores.
  - Medir el tiempo de respuesta de `GET /api/v1/productos/` y `GET /api/v1/auth/login` bajo carga.
  - Monitorizar uso de CPU/memoria del contenedor `api` durante la prueba.

- **Observaciones:**  
  - No hay evidencia de cumplimiento: ningún test de carga, benchmark ni configuración de escalado horizontal.
  - Las métricas objetivo están documentadas en `doc/requirements/non-functional.md` (RNF-01.1 a RNF-01.6).
