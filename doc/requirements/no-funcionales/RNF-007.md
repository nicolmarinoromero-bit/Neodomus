# RNF-007 — Portabilidad (navegadores)

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RNF-007 |
| Nombre | Portabilidad (navegadores) |
| Categoría | Compatibilidad |
| Prioridad | Media |
| Estado | Implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El software debe ejecutarse correctamente en los navegadores Chrome, Edge y Firefox.

- **Criterio:**  
  - Funcionamiento correcto en Google Chrome, Microsoft Edge y Mozilla Firefox (últimas dos versiones de cada uno).
  - Sin errores de renderizado ni de funcionalidad dependientes del navegador.

- **Implementación actual:**  
  - El frontend está construido con **React 18 + Vite + TypeScript** y estilos propios en CSS (sin dependencia de APIs propietarias de navegador), lo que garantiza compatibilidad estándar.
  - La restricción del proyecto (RC-03.2) exige soporte para Chrome, Edge y Firefox, y el desarrollo se verifica en Chrome DevTools; no se usan extensiones ni polyfills específicos de un navegador.
  - `vite.config.ts` apunta el build a `fe` con TypeScript estricto; la configuración ESLint (`eslint.config.js`) cubre los tres entornos.
  - La app usa características web estándar (fetch/Axios, localStorage, CSS Grid/Flexbox, media queries) presentes en los tres navegadores modernos.

- **Evidencia técnica:**  
  - `fe/package.json` → React 18, Vite 5, TypeScript estricto
  - `fe/vite.config.ts`, `fe/tsconfig.app.json`, `fe/eslint.config.js`
  - `fe/src/styles/*.css` (CSS estándar con media queries)
  - `doc/requirements/constraints.md` → RC-03.2 (soporte obligatorio Chrome/Edge/Firefox)

- **Validación:**  
  - Ejecutar los flujos principales (registro, login, catálogo, citas, paneles) en Chrome, Edge y Firefox (últimas versiones).
  - Usar las herramientas de desarrollador de cada navegador para revisar consola y errores de red.
  - Ejecutar `pnpm tsc --noEmit` y `pnpm lint` para garantizar código sin errores.

- **Observaciones:**  
  - No existe una suite de pruebas de compatibilidad entre navegadores (p. ej. Playwright/Selenium), pero el código usa APIs estándar y no hay evidencias de incompatibilidad.
