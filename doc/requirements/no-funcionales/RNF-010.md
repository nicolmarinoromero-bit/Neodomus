# RNF-010 — Accesibilidad

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RNF-010 |
| Nombre | Accesibilidad |
| Categoría | Experiencia de usuario |
| Prioridad | Media |
| Estado | Parcialmente implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El sistema debe ser accesible para personas con discapacidad visual parcial mediante compatibilidad con lectores de pantalla.

- **Criterio:**  
  - Los elementos interactivos deben poder ser leídos y operados con lectores de pantalla (WCAG 2.1 nivel AA según documentación interna).
  - Contraste de texto adecuado, alternativas textuales para imágenes y navegación por teclado.

- **Implementación actual:**  
  - **Atributos `aria-*` ampliamente usados** (más de 78 marcadores en el frontend): `aria-label` en botones de acción (carrito, favoritos, notificaciones, paginación, menús), patrones `tablist/tab/tabpanel` en Ayuda y Citas, `role="radiogroup"` para las horas de cita, `role="switch"` con `aria-checked` en las preferencias, `aria-required` en formularios, `role="dialog"` y `aria-expanded` en el chatbot, además de `alt` en las imágenes de productos y `aria-hidden` en elementos decorativos.
  - Navegación semántica con encabezados y etiquetas de formulario en las páginas principales.
  - Se respeta `prefers-reduced-motion: reduce` para el fondo animado (`fe/src/styles/ambient.css`).
  - **Limitaciones:** no hay auditoría WCAG formal ni pruebas con lectores de pantalla reales (p. ej. NVDA/ VoiceOver); algunos patrones podrían requerir ajustes (validación de contraste y foco visible). Los colores institucionales negro/dorado pueden suponer retos de contraste en algunos componentes.

- **Evidencia técnica:**  
  - `fe/src/pages/cliente/AyudaPage.tsx`, `CitasPage.tsx`, `fe/src/pages/public/ProductosPublicos.tsx`
  - `fe/src/components/chat/ChatBotWidget.tsx`, `fe/src/components/profile/NotificationsTab.tsx`
  - `fe/src/components/layout/AdminNavbar.tsx` (menú con `aria-label`)
  - `fe/src/styles/ambient.css` (`prefers-reduced-motion`)
  - `doc/requirements/non-functional.md` → RNF-05.2 a RNF-05.4, RNF-10.1

- **Validación:**  
  - Ejecutar una auditoría con Lighthouse/Axe Core y comprobar la puntuación de accesibilidad.
  - Probar los flujos principales con un lector de pantalla (NVDA en Windows o VoiceOver en macOS).
  - Verificar navegación completa por teclado (foco visible y orden lógico) y los contrastes ≥ 4.5:1.

- **Observaciones:**  
  - La base de accesibilidad está presente (ARIA, semántica, reduced-motion), pero falta una verificación formal WCAG 2.1 AA y el ajuste de contraste de la paleta institucional en algunos componentes (la restricción RC-05 y la doc interna RNF-05.2 lo exigen).
