# RNF-004 — Fiabilidad

- **Identificación:**

| Campo | Valor |
|---|---|
| ID | RNF-004 |
| Nombre | Fiabilidad |
| Categoría | Disponibilidad y respaldo |
| Prioridad | Media |
| Estado | Parcialmente implementado |
| Fecha | Mayo 2026 |

- **Descripción:**  
  El sistema debe garantizar una disponibilidad del 99% y realizar un respaldo automático de los datos cada 24 horas.

- **Criterio:**  
  - Disponibilidad del servicio ≥ 99% en horario comercial.
  - Copia de seguridad automática de la base de datos cada 24 horas.
  - Restauración posible desde la última copia (RTO ≤ 2 h, RPO = 24 h según documentación interna).

- **Implementación actual:**  
  - La base de datos se persiste mediante el **volumen Docker `mysql_data`**, lo que la mantiene entre reinicios del contenedor.
  - La migración inicial de Alembic es idempotente (`CREATE TABLE IF NOT EXISTS`), lo que facilita recuperar el esquema sobre una base existente sin pérdidas.
  - **No existe un proceso de backup automático**: no hay `mysqldump`, cron ni servicio de respaldo; la disponibilidad no está medida (sin SLI/SLO ni monitorización).
  - No hay reintentos automáticos con backoff exponencial para APIs externas (solo existe SMTP síncrono con timeout, sin reintentos).

- **Evidencia técnica:**  
  - `docker-compose.yml` → volumen `mysql_data`
  - `be/alembic/versions/0001_baseline_esquema_inicial.py` → migración idempotente
  - `be/app/utils/email.py` → SMTP con `timeout=10` (sin reintentos)
  - `README.md` → instrucciones de arranque con `alembic upgrade head` automático
  - `doc/requirements/non-functional.md` → RNF-02.1 a RNF-02.5

- **Validación:**  
  - Verificar que existe un respaldo generado automáticamente en las últimas 24 horas (no existe).
  - Probar la restauración de la base desde una copia y medir el tiempo.
  - Monitorizar el uptime del servicio y calcular el porcentaje de disponibilidad.

- **Observaciones:**  
  - La persistencia por volumen Docker protege ante reinicios, pero no constituye una copia de seguridad automática de 24 horas (RF-040 tampoco está implementado).
  - No se mide la disponibilidad ni hay monitorización de salud en producción.
